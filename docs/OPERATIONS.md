# Настройки и эксплуатация

[Оглавление](README.md)

## Конфигурация и секреты

`app.Configuration` — стандартная конфигурация ASP.NET Core: appsettings, environment,
command line и подключённые провайдеры. Trexon.Configuration можно использовать для
типизированных env-настроек, как в примере; библиотека не навязывает этот пакет.

Секрет JWT должен быть случайным и стабильным между перезапусками нужных экземпляров.
Репозиторий не содержит рабочего signing key, admin password или API key. `.env`,
варианты `.env.*`, локальные БД, IDE-файлы и результаты сборки исключены `.gitignore`.
`.env.example` содержит только имена настроек и пустые значения.

JWT-ключ примера при отсутствии настройки генерируется на процесс: это позволяет
первый запуск одной командой. Перезапуск такого примера делает предыдущие access tokens
невалидными; refresh-сессии в SQLite сохраняются и могут получить новые токены после
проверки актуальным экземпляром. Для воспроизводимого состояния задайте свой секрет.

## HTTPS и reverse proxy

HTTP по умолчанию в локальном примере предназначен для локального знакомства.
Cookie-endpoints требуют HTTPS. В production используйте HTTPS на Kestrel либо
TLS termination на доверенном proxy. Настраивайте ForwardedHeaders только для
известных прокси/сетей: от этого зависят схема URL, RemoteIpAddress и лимиты клиентов.
Подключение нестандартного порядка middleware возможно через стандартный builder;
библиотека не включает доверие ко всем forwarded-заголовкам автоматически.

Чтобы запустить локальный пример с сертификатом разработки:

```sh
dotnet dev-certs https --trust
TREXON_URL=https://localhost:7080 dotnet run --project examples/Trexon.Web.Sample
```

Команда доверия сертификату выполняется пользователем при необходимости. Следуйте
локальным сообщениям SDK. Для команды с `TREXON_URL=...` показан синтаксис POSIX shell;
в PowerShell используйте `$env:TREXON_URL = "https://localhost:7080"`.

## Состояние

SQLite-аккаунты и задачи примера хранятся в двух файлах. Выберите `TREXON_DATA_DIR`,
сохраните каталог в volume и делайте резервные копии согласованным способом SQLite
(backup API либо остановка писателя с учётом WAL). Копирование только основного файла
при активном WAL может пропустить данные. Схема accounts создаётся при startup;
полноценного механизма миграций аккаунтов пока нет.

Cookie Data Protection keys по умолчанию зависят от настроек хоста. Для контейнеров
и нескольких экземпляров настройте постоянный общий key ring и application name.
API key storage выбирает приложение; пример использует один ключ из окружения.

Rate limit и output cache в текущих модулях локальны процессу. Несколько реплик
не разделяют лимит или кеш автоматически. Для распределённого решения подключайте
соответствующие ASP.NET Core providers/свой модуль.

## Наблюдаемость и завершение

Request logging не записывает body/query/credentials. Обычные server exceptions
попадают в ILogger, поэтому полезно подключить настроенный logging provider. Health
checks показывают только статусы проверок, без connection strings и stack traces.
Защиту доступа к инфраструктурным endpoints задавайте на уровне приложения/сети.

`RunAsync` использует стандартный graceful shutdown. Для middleware и I/O передавайте
RequestAborted, для startup — токен BuildAsync. Отмену не следует подавлять и превращать
в успешный ответ. Дополнительных фоновых процессов библиотека не создаёт.
